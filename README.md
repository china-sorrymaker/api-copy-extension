# API Copy v1.4.1

- 默认只展示 Fetch/XHR 等接口，过滤 JS/CSS/图片/字体/HTML 等资源。
- 通过 DevTools HAR 快照每 1.2 秒与当前请求集合对账，连续两次确认消失则删除旧请求。
- 左侧一键复制、分栏拖动、复制模式均保留。

## JSON 响应预览

- 折叠行显示字段和值的摘要，例如 `{id: "...", operationTime: "...", …}`，数组显示长度和内容轮廓。
- 字段、字符串、数字、布尔值、null 使用不同颜色；长行在响应区内横向滚动。
- 按需创建折叠内容；支持全部展开、全部折叠，切换请求和新请求到来时保留各请求的展开与滚动位置。
- 摘要继续使用脱敏后的数据；复制响应仍是完整格式化内容，不受摘要截断影响。

## 复制与布局

- 采用清爽分栏布局，右上角齿轮打开脱敏设置，默认收起；支持点击外部或按 Esc 关闭。
- 操作顺序：完整复制、精简复制、复制 URL、复制 URI、复制入参、复制返回值。
- URL 包含协议、域名、路径及查询参数；URI 只保留路径与查询参数，两者均按现有规则脱敏。
- 单独复制入参：JSON Body 直接复制 JSON；Query 转成 JSON，保留字符串及重复参数数组；两者同时存在时输出 `{ "query": {...}, "body": {...} }`。
- JSON 空对象、空数组和 null 单独复制时原样保留；无入参显示“无入参”。非 JSON 文本 Body 保留文本，不复制文件内容。
- 完整复制、精简复制与页面展示仍保留 Query / Body 来源标记。

## 请求头脱敏

- 普通请求头及普通自定义业务头默认保留明文，无需逐一配置。
- Auth、Token、Cookie、Secret、Api-Key 等敏感头，以及 Bearer / Basic / Token / crypto 认证内容始终脱敏。
- “不允许明文的请求头”填写额外需要脱敏的完整头名，例如 `company-ticket, login-sign`。忽略大小写，以逗号、分号或空白分隔，不支持通配符。留空时仍保留内置敏感规则。
- 首尾保留长度及星号数量沿用现有配置，短值显示 `[REDACTED]`。配置自动保存在本地，完整复制、精简复制及列表复制共用规则。
- 仅处理复制结果，不修改实际网络请求。凭据使用特殊头名且未命中内置规则时，请加入“不允许明文的请求头”。旧版明文名单不会转换为脱敏名单，首尾长度及星号数量继续保留。

本地检查：`node --test tests/*.test.js`（在插件目录执行）。

## 手动验证

1. 在 `chrome://extensions` 重新加载插件，关闭并重新打开 F12，进入 API Copy。
2. 触发一个 JSON Body 接口，点击“复制入参”，应得到可以直接解析的 JSON，没有 `Body:` 前缀。
3. 触发带 Query 的接口，确认 Query 值保留字符串；Query / Body 同时存在时，复制结果按 `query`、`body` 分组。
4. 点击“复制 URL”和“复制 URI”，确认前者含协议和域名，后者只含路径及查询参数，敏感查询参数仍脱敏。
5. 点击右上角齿轮，填写额外脱敏的头名；复制完整信息检查效果，关闭并重开 F12 后确认配置保留。

## 限制
Chrome 扩展 API 不暴露 Network 面板的 UI 筛选器或专门的 Clear 事件，也不保证 HAR 与原生 Network 的界面结果完全相同。因此只能尽力保持请求集合同步，不能承诺强一致。
对于服务端返回 text/plain 的接口，若 Chrome 没标记为 Fetch/XHR，可能需要放宽过滤规则。

安装：解压 ZIP → chrome://extensions → 加载已解压的扩展程序 → 重新打开 F12。
